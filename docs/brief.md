# SSH File Drop：macOS ドロップレット実装依頼書

## 1. 作りたいもの

macOS でファイルを小さなアプリのアイコンにドロップすると、選択した SSH 接続先の `/tmp` 配下へ転送し、転送先の絶対パスがクリップボードに入るアプリを実装してください。

ターミナルや LLM との会話へファイルパスを渡すまでの手間を減らすことが目的です。Raycast の導入や Herdr 本体の改修は前提にしません。本書は実装仕様であり、アプリの完成や動作検証を報告するものではありません。

## 2. MVP の利用体験

1. ユーザーが Finder の通常ファイルを、Dock または Finder 上のアプリアイコンにドロップする。
2. SSH 接続先の Host エイリアスを選ぶ。前回成功した接続先を初期選択する。
3. 選択先とファイル名を確認できる「転送」操作で開始する。
4. 転送中であることを表示する。画面を固めず、キャンセルできる。
5. 転送完了後、リモートの絶対パスをローカルのクリップボードにコピーし、成功を表示する。

出力例：`/tmp/ssh-file-drop.a1B2c3D4/議事録.pdf`

コピーするのはパスだけです。Host 名、説明文、コマンド、引用符は付けません。自動ペーストや Enter の送信は行いません。空白などを含むパスをシェルへ貼る場合は別途引用が必要ですが、MVP では LLM 等にも渡しやすい生の絶対パスを標準にします。

## 3. 対象と対象外

### 必須

- macOS の AppleScript ドロップレット、または Automator のアプリケーション形式。
- 一度に通常ファイルを一つ受け取る。拡張子や内容を画像に限定しない。
- システム標準の `ssh` と `scp`、既存の SSH 設定と鍵・エージェントを利用する。
- 接続先ごとに独立した一意の一時ディレクトリを作り、元のベース名を保持する。
- Linux／macOS 等の一般的な SSH 接続先を想定し、実際の対応 OS と必要コマンドを明記する。

### MVP では対応しない

- 複数ファイル、ディレクトリ、シンボリックリンク。該当する入力は転送前に理由を示して拒否する。リンクを黙ってたどらない。
- Herdr のペインや実行中の SSH セッションの自動検出。
- Raycast／Tinycast 拡張、常駐サーバー、独自認証、独自 SSH クライアント。
- ローカルへのコピー、転送先の自動削除スケジュール、ファイル内容のプレビュー。

複数ファイル対応や Finder のクイックアクションは追加機能として分離し、MVP 完了の条件にしないでください。

## 4. 最小構成

### A. ドロップレット

AppleScript の `open` ハンドラ等で入力を受け取り、接続先の選択、進捗、キャンセル、結果表示を担当します。転送ロジックを UI のスクリプトに埋め込みすぎないでください。

### B. 共通の転送ヘルパー

入力検証、SSH 呼び出し、一時領域の作成、転送、確定、失敗処理を担当します。引数でファイルと接続先を受け取り、成功時のパスとエラーを区別して返します。クリップボード更新は成功結果を受けた後に行います。外部ランタイムの導入はなるべく避け、必要なら理由と導入方法を説明してください。

### C. 任意の Finder クイックアクション

同じヘルパーを呼び出す薄い入口にします。別実装の転送処理を持たせません。

## 5. SSH 接続先と認証

- 最初は少数の Host エイリアスを設定できるだけで十分です。最後に成功したエイリアスのみ記憶し、秘密情報は保存しません。
- `~/.ssh/config` の設定解決は OpenSSH に任せます。`Include`、`Match`、ワイルドカードを考慮せず `Host` 行だけを拾い、「全接続先に対応」と扱わないでください。候補抽出を実装する場合は制約を明示し、明示的な候補登録を残します。
- Host 入力をシェル断片や SSH オプションとして解釈させないこと。先頭の `-`、改行、制御文字等を拒否し、実際の呼び出しは引数境界を保ちます。
- Finder／Dock からの起動と Terminal からの起動では環境変数や SSH エージェントの利用状況が異なり得ます。ログインシェルの設定が読み込まれる前提にしません。
- パスワードや鍵のパスフレーズをアプリ内で取得・保存しません。既存の鍵・エージェントで非対話接続できない場合は明確に失敗し、Terminal で同じ Host への接続を確認する手順を案内します。
- 未登録または変更されたホスト鍵は失敗させます。`StrictHostKeyChecking=no`、known_hosts の無効化、自動的な鍵の信頼は行いません。初回確認はユーザーが通常の SSH で行います。

## 6. 転送の安全性と完了判定

### 一時領域と公開タイミング

1. リモート側で `umask 077` を適用し、`mktemp -d` 等により `/tmp/ssh-file-drop.<一意な値>` を作ります。作成方法の OS 差異を確認してください。
2. ディレクトリは所有者のみアクセス可能な `0700` にします。返されたパスは期待する親ディレクトリと接頭辞を検証し、予期しない SSH 出力をパスとして扱いません。
3. その中の未完成用ファイル名へアップロードします。最終ファイル名と衝突しない方法を選びます。
4. 転送プロセスの正常終了を確認し、サイズ等による完了確認を行います。転送元が途中で変化した場合も成功と誤認しないよう扱います。ハッシュ比較は必要性とコストを見て追加できます。
5. ファイルの権限を `0600` に整え、同じディレクトリ内で元のベース名へ rename して確定します。
6. 確定処理まで成功した場合だけ、最終パスをコピーします。

同名ファイルの再転送は別ディレクトリに保存し、以前の成功ファイルを上書きしません。`/tmp` は永続ストレージではなく、OS 等によって消える可能性があることを利用手順に記載します。

### 引数とファイル名

空白、日本語、絵文字、アポストロフィ、先頭のハイフン、シェル記号を含むファイル名を安全に扱ってください。ローカルでの引数分離だけでなく、SSH のリモート側でコマンドがどう解釈されるかまで確認します。文字列連結、`eval`、未引用の変数展開でコマンドを組み立てないでください。

`scp` の転送方式やバージョンによるパス解釈の違いも確認し、対応範囲で検証します。改行や制御文字を含むファイル名は、MVP では明示的に拒否して構いません。

### 失敗とキャンセル

- 接続失敗、認証失敗、容量不足、転送失敗、検証失敗、キャンセル時は既存のクリップボードを変更しません。
- 接続タイムアウトと通信断の検出を設定し、無期限に待ち続けません。キャンセルは関連プロセスも停止させます。
- 削除対象は、この実行で作成し所有を確認できた未完成領域だけです。広いワイルドカードや `/tmp` 全体の削除は禁止します。
- 接続断で後始末できない場合は、その事実を報告します。削除できたと断言しません。成功ファイルを勝手に削除しません。
- 転送成功後にクリップボード更新だけ失敗した場合は、成功したリモートパスを表示し、再コピーできるようにします。転送そのものを失敗扱いして無条件に再実行しません。
- ログには認証秘密やファイル内容を残しません。ユーザーが選んだファイル以外を送信しません。

## 7. 受け入れテスト

最低限、以下を確認して結果を添えてください。

- Finder／Dock へのドロップから転送、パスのコピーまで完了する。
- 前回成功した Host が初期選択され、別 Host に変更できる。
- 空ファイル、通常ファイル、大きめのファイルを転送できる。
- 日本語、空白、アポストロフィ、先頭 `-`、`$()` や `;` を含む名前がコマンドとして実行されない。
- 同名ファイルを二度転送しても既存ファイルが上書きされない。
- ディレクトリ、シンボリックリンク、複数入力を理由付きで拒否する。
- 未知／変更済みホスト鍵、認証失敗、接続不能、転送途中の切断、キャンセルで成功表示やクリップボード更新が発生しない。
- 完成ファイルが `0600`、専用ディレクトリが `0700` である。
- Terminal では成功するが GUI 起動時にエージェントが利用できない場合も、固まらず対処を案内する。
- クリップボード更新失敗と後始末失敗を、転送状態と区別して報告する。

## 8. 納品物

- ドロップレットと共通ヘルパーのソース。
- macOS で再現可能な `.app` の作成手順。可能なら生成済みアプリも添付。
- 接続先設定、初回 SSH 確認、Dock への配置、利用、削除の簡潔な手順。
- 対応 macOS／リモート OS、依存コマンド、既知の制限。
- テスト結果。実機で確認した項目、静的確認のみの項目、未検証の項目を明確に分けること。実際の SSH 接続や GUI 操作を行っていない場合、動作確認済みと記載しないこと。

まずこの MVP を完成させてください。機能追加や大きなフレームワークの採用より、失敗時に壊さず、毎回同じ手順で使えることを優先します。
